## 1. 自動テストとビルド検証

- **仮想環境の構築**: `uv sync --locked` で検証用仮想環境を作成（ポート8000番で旧サーバーが稼働していたため、稼働中の実行ファイルを置き換えず別環境で実施）。
- **単体・結合テスト**: `uv run --locked pytest` 相当で **全143件成功**（依存先のStarletteが `httpx` の将来の非推奨化に関する警告を1件出しますが、テスト失敗はありません）。
- **静的解析・フォーマット**: `ruff check`、`ruff format --check`、`git diff --check` がすべて成功。
- **パッケージビルド**: `uv build` で `sdist` と `wheel` を作成し、配布物の中に `.env`、認証情報、状態DB、仮想環境が含まれていないことを確認。
- **配布物のインストール確認**: 別の仮想環境にロック済み依存パッケージとビルド済み `wheel` をインストールし、配布パッケージからの `import` とAPIアプリケーションの構築を確認。

### テストでカバーしている主な項目

- **入力処理・プロトコル**:
  - 抽出原文の前後空白・改行・タブの完全保持、AIRIの入力装飾（日時・返信先・スキル・Context）の除去
  - 不可視ヘッダー付き投稿と履歴照合、全9種類の感情コードの復号と変換
  - フッター欠落・未知コード・署名破損・重複フッター・引用や本文内の不可視文字保持
  - 補助推論（Cinematic Director等）・Notice通知・非対応パラメータの拒否
- **API・ワーカー制御**:
  - SSEストリーミングと通常JSONレスポンス、`ACT` マーカーの付与と無効化設定
  - Bearer認証、CORSプリフライト、タイムアウト、同時リクエストの共有と排他制御
  - プロセス再起動後の保留移行・履歴照合（`reconcile`）・保留解除（`clear-pending`）
  - 別プロセスのUvicornへ実HTTPで接続し、クライアント途中切断後に同一リクエストを再送してもテスト用Museバックエンドへの投稿が1回だけになることの確認
- **0.1.0からのマイグレーション**:
  - 旧DBの移行前バックアップ作成（`journal.pre-v2.sqlite3`）
  - すべての旧保留状態の自動再投稿禁止、旧完了キャッシュの非再解釈（`neutral` 固定）
  - 期限切れの旧識別子の保持（再投稿防止）、新方式でのキャッシュ再生
  - `payload.content` と `display_text` が異なるケースでの `payload.content` 優先採用と欠落時エラー

## 2. 実際のMuseへの読み取り接続確認

- **履歴読み取り診断**: `0.2.0` の環境から既存の認証情報を用いて履歴を読み取り、接続の成功を確認しました。この診断によるメッセージ投稿や `muse-cli` 設定ファイルの変更はありません。
- **不可視文字の往復保持の実証**:
  - ユーザーが事前にMuse UIで行った不可視文字の往復テストを履歴から再確認しました。
  - `user` の48文字はUTF-8の「ねこ」、`assistant` の72文字は「めいど」に復号でき、`payload.content`・`payload.display_text`・トップレベル `display_text` のすべてが一致していました。
  - ※これは不可視2文字種（`U+200B` / `U+200C`）の保持と復号の実証であり、新しい `AIRI1` / `AE1:` 規約自体の遵守率を実証したものではありません。
- **0.1.0時点での実機確認事項**:
  - `0.1.0` 作成時には、製品版CLIのローカルHTTP起動、モデル一覧取得、ローカル接続検証（`ping`）を確認しています。
  - その際、一度Muse側がWebSocket接続を拒否し、元からインストールされている `muse-cli` でも同じ失敗が発生しました。ブリッジはこの状態を想定どおり `503 / muse_unavailable` として返しました。実接続の可否は外部サービスの状態に依存するため、利用時に `doctor` コマンドで再確認してください。

## 3. 未検証項目と実機反映手順

### 未検証項目

- 今回の `0.2.0` 更新作業では、実際のMuseへの新規投稿やソウルの編集は行っていません。
- 「新しいヘッダー付き入力 → Museによる `AE1:` フッター生成 → `ACT` マーカーへの変換」の実機往復は、ソウル追記後に確認が必要です。
- AIRIの実画面を通じた接続、音声読み上げ、口パク、アバター表情の動作は未検証です。
- AIRI v0.14.1以外のバージョンや、ユーザーが追加した独自の補助推論は動作保証していません。

### 実機への反映手順

1. 稼働中の旧サーバーを停止し、`uv sync --locked` を実行したうえでサーバーを再起動します。
2. [ソウル追記用プロンプト](muse-soul-addendum.md) をMuseのソウルへ追記します。
3. AIRIから短い発言を送り、Museの履歴に「不可視ヘッダー＋原文」が1件だけ追加され、返信末尾のフッターが `ACT` マーカーへ変換されることを確認してください。
